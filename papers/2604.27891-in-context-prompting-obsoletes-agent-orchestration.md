# In-Context Prompting Obsoletes Agent Orchestration for Procedural Tasks

- **arXiv**: http://arxiv.org/abs/2604.27891v1
- **Published**: 2026-04-30
- **Authors**: Simon Dennis, Michael Diamond, Rivaan Patil, Kevin Shabahang
- **Category**: cs.AI / cs.CL / cs.LG
- **Keyword match**: Google ADK, OpenAI Agents SDK

## 概要

LangGraph, CrewAI, Google ADK, OpenAI Agents SDKなど主要なエージェントオーケストレーションフレームワークを、より単純な代替手法と比較した制御実験。結果、**手続き的タスクでは外部オーケストレーターを使うより、プロシージャ全体をシステムプロンプトに書いてモデルに自己オーケストレーションさせる方が優れている**ことを示す。

## 実験設定

3つのドメインで比較:
- 旅行予約（14ノードのワークフロー）
- Zoom技術サポート
- （追加ドメイン）

## 主な発見

- 外部オーケストレーターはターンごとにルーティング指示を注入するが、これはLLMの能力の重複
- シンプルなin-contextプロンプティングがオーケストレーションフレームワークを精度・コスト双方で上回る
- 複雑なフレームワーク導入が不要なケースが多い

## 意義

エージェント設計のパラダイムに疑問を投げかける重要研究。「エージェントフレームワークは本当に必要か？」という実務的問いに対する実証的答え。
